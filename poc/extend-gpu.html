Multicloud PoC flow · GPU on your own Kubernetes

From sign-up to an LLM on your own Kubernetes

Every step where you act or enter data. At the end, a vLLM server with Qwen2.5-7B runs on one NVIDIA L4 or A10G GPU in your AWS account. Your on-prem cluster uses that GPU as if it were a local node, and you send prompts to the model from your laptop.

Have these ready

  • A work email address
  • An AWS account ID (12 digits)
  • An AWS account (a new one is fine: the page shows how to set it up)
  • A laptop with macOS, Linux, or Windows 10/11 (with WSL2)
  • Optional: an AI agent that can run terminal commands and use MCP servers
  • A kubeconfig with cluster-admin rights on your Kubernetes cluster (1.30+)
  • Your pod and service CIDRs, and your CNI name
  • Your egress path: direct, HTTPS proxy or TLS inspection
  • A spend limit per hour (we suggest $1.50)

What you end up with

Your cluster gets one virtual node. A pod you place on it runs on a real GPU worker in your AWS account. Multicloud runs the control plane of that worker pool and keeps one worker running while the pool is awake. You hibernate the pool to stop paying for the worker. Your control plane, your other nodes and your data stay where they are.

Send a query to the model

vLLM speaks the OpenAI API. For the PoC you call it through kubectl port-forward: there is no public URL and no extra tunnel. While the port-forward runs, the model answers on your laptop at:

http://localhost:8000/v1/chat/completions
  • Model name: qwen (Qwen/Qwen2.5-7B-Instruct, up to 8,192 tokens of context).
  • Every request needs the header Authorization: Bearer <key>. The key is in the secret vllm-api-key.
  • The port-forward works only while its terminal stays open, and only for the person who runs it.
  • The request goes through your API server, the Liqo bridge, Cloudflare and the Multicloud pool API server to the GPU worker. The response comes back the same way.
curl (in your first terminal)
export KEY=$(kubectl -n my-apps get secret vllm-api-key \
  -o jsonpath='{.data.key}' | base64 -d)

curl -s http://localhost:8000/v1/chat/completions \
  -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen","messages":[
        {"role":"user","content":"Say hello."}]}'
Python (after: uv pip install openai, or pip install openai)
# Run in the same terminal, after the export KEY=... line
import os
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8000/v1",
                api_key=os.environ["KEY"])
r = client.chat.completions.create(
    model="qwen",
    messages=[{"role": "user", "content": "Say hello."}])
print(r.choices[0].message.content)
Example response (shape only; the text varies)
{"object": "chat.completion", "model": "qwen",
